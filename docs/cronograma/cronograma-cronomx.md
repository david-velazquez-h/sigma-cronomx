# Cronograma — CronoMX / SIGMA

**Objetivo del semestre:** llegar a una versión **estable** (no solo un MVP) para mediados de diciembre 2026.

Este documento define el avance esperado mes a mes, más el desglose semanal (que David enviará cada lunes, con revisión de equipo cada viernes).

---

## Vista general por mes

| Mes | Meta principal | Entregable al cierre del mes |
|---|---|---|
| **Septiembre** | Investigación, cimientos y UX | Literatura revisada, GTFS limpiado, primeras fórmulas exploradas, wireframes de las 4 pantallas clave definidas, fórmula del índice cerrada |
| **Octubre** | Diseño visual y backend | Diseño de UI aplicando marca CronoMX (logos ya existentes), backend con API funcionando sobre datos reales (Miguel) |
| **Noviembre** | Construcción e integración | Frontend construido sobre los wireframes aprobados, mapa interactivo desplegado con los municipios piloto, comparador de rutas funcionando end-to-end |
| **Diciembre (1ª quincena)** | Pulido y difusión | Versión estable, documentación de metodología terminada, repo público presentable, primer acercamiento institucional/académico hecho |

> Nota: "estable" significa que el mapa y el comparador de rutas funcionan de principio a fin sin errores con los municipios piloto definidos, no necesariamente cubrir toda la ZMVM. Eso queda para una v2 fuera del semestre.
>
> **Ajuste respecto al plan original:** el equipo se adelantó en investigación y datos, así que se movió el diseño de experiencia de usuario (wireframes) a septiembre, antes de escribir código de frontend, esto pues evita construir pantallas que luego haya que rehacer.
